# bank-churn-to-retention

Pet-проект по продуктовой аналитике: EDA оттока клиентов банка, дашборд в Apache Superset и симулированный A/B-тест на уменьшение оттока клиентов.


## Обзор

Продуктовый аналитический кейс на датасете Kaggle Bank Customer Churn — данные о 10 000 клиентов банка и 18 признаках, описывающих их профиль и поведение. В рамках кейса выполнено исследование данных и формулировка гипотез об оттоке с помощью python pandas, осбран дашборд в Apache Superset. Поскольку провести реальный A/B-тест на этих данных невозможно, был смоделирован A/B-тест на удержание клиентов на синтетических данных — чтобы показать, как бы выглядела проверка одной из гипотез в реальном продукте. 

## Гипотезы и находки по итогам EDA

**Подтверждённые находки (на основе данных):**

- Общий отток клиентов — **20.4%**.
- Наибольший отток у клиентов с 3-4 продуктами(60-100%)
- Отток в **Германии (32.4%)** почти вдвое выше, чем во Франции и Испании (~16%).
- Клиенты 46–65 лет уходят чаще других возрастных групп.

**Бизнес-гипотезы, требующие проверки (не выводятся напрямую из данных):**

1. **Невыгодные условия для клиентов с большим количеством продуктов.** У конкурентов условия лучше. Стоит проверить, были ли недавние изменения условий для таких клиентов и насколько банк конкурентоспособен на рынке по этому сегменту продуктов.
2. **Изменения условий в Германии.** Стоит проверить последние запуски/изменения условий обслуживания именно в Германии — возможно, там тоже произошли невыгодные для клиентов изменения.
3. **Неудобства перехода в онлайн-формат для пожилых клиентов.** Переход на цифровое обслуживание или другие изменения условий могли оказаться неудобными именно для пожилого поколения и повлиять на их отток.
4. **Коммуникация, ориентированная на молодую аудиторию.** Реклама или явная политика компании в сторону привлечения исключительно молодёжи могла восприниматься пожилыми клиентами как исключающая и повлиять на их уход.
5. **Внешнеполитическая ситуация.** Внешнеполитическая обстановка могла повлиять на решение о закрытии .

## Дизайн A/B-теста

**Гипотеза.** Клиенты с 3 продуктами банка показывают высокий отток (82.7% по реальным данным) — вероятно, из-за невыгодных условий для этого сегмента. Если улучшить условия лояльности (персональный менеджер, повышенный кэшбэк, льготные ставки), отток должен снизиться.

Клиенты с 4 продуктами исключены из эксперимента: их отток уже близок к 100% почти во всех возрастных группах, там физически нет пространства для измеримого улучшения.

**Параметры теста:**

| Параметр | Значение |
|---|---|
| Популяция | клиенты с 3 продуктами банка |
| Метрика | доля ушедших клиентов (churn rate) |
| Baseline (реальный отток в сегменте) | 82.7% |
| MDE | 10 п.п. |
| Уровень значимости / мощность | α = 0.05 / 80% |
| Тест | two-proportion z-test, двусторонний |
| Нужно клиентов на группу / всего | 269 / 538 |

**Ограничение.** В датасете всего 266 клиентов с 3 продуктами — реальной выборки не хватает даже на одну группу теста (нужно 269). Это ограничение, зафиксированное как есть, подгонка MDE под количество клиентов исказило бы интерпретируемость результата. На практике это значит, что перед реальным запуском теста банку нужно либо расширить критерии участия, либо накопить больше данных за более длинный период.

Чтобы всё равно показать, как бы выглядел результат такого теста, отток для обеих групп смоделирован на синтетических данных (`numpy`, `np.random.binomial`) — с реальным baseline в качестве вероятности оттока контрольной группы и (baseline − MDE) для тестовой.

## Результаты A/B-теста

На смоделированных данных (n = 269 на группу):

| Группа | Отток |
|---|---|
| Контрольная | 81.8% |
| Тестовая | 68.4% |

Разница — 13.4 п.п., что превышает целевой MDE (10 п.п.).

**Two-proportion z-test:** Z = 3.589, p-value = 0.0002 — результат статистически значим (p ≪ 0.05), нулевая гипотеза отвергается.

**Вывод.** Если бы улучшенные условия лояльности были внедрены для сегмента клиентов с 3 продуктами, можно было бы ожидать статистически значимое снижение оттока — как минимум на заложенные 10 п.п.

**Дополнительный срез по странам.** Синтетические клиенты внутри обеих групп были условно распределены по странам в тех же пропорциях, что наблюдались в реальных данных сегмента. Подгруппы здесь маленькие (67–111 человек — заметно меньше требуемых 269) и отдельно на мощность не проверялись, поэтому результат ниже не доказан статистически, а является сигналом для дальнейшего исследования:

| Страна | Контроль | Тест | Разница |
|---|---|---|---|
| Германия | 85.7% | 66.0% | −19.7 п.п. |
| Испания | 80.6% | 63.9% | −16.7 п.п. |
| Франция | 79.3% | 74.0% | −5.3 п.п. |

Эффект выглядит сильнее в Германии и Испании, чем во Франции — это частично согласуется с гипотезой о специфичных для Германии изменениях условий (см. раздел "Гипотезы"), но ввиду маленькой выборки на страну эту гипотезу стоит проверять отдельным, целенаправленным тестом, а не делать вывод на основе этого среза.

**Рекомендация.** Результаты симуляции говорят в пользу пилотного запуска улучшенных условий лояльности для сегмента клиентов с 3 продуктами — в первую очередь с прицелом на Германию и Испанию, где потенциальный эффект выглядит наиболее выраженным. Перед запуском реального теста нужно либо расширить сегмент, либо дать время на накопление достаточного объёма данных (269 клиентов на группу).

## Особенности

- **EDA в pandas**: очистка данных, распределения, корреляционный анализ (pandas, matplotlib, seaborn, scipy, statsmodels).
- **Витрина данных в PostgreSQL**: загрузка очищенного датасета из Jupyter Notebook через SQLAlchemy.
- **Контроль за размером выборки**: там, где сегмент оказывался статистически маленьким, метрика пересчитана в абсолютные числа, чтобы не вводить в заблуждение процентом на единичных наблюдениях.
- **Симулированный A/B-тест**: так как провести реальный эксперимент невозможно, тест смоделирован на синтетических данных.

## Технологический стек

- **Python** — pandas, numpy, matplotlib, seaborn, scipy, statsmodels
- **Jupyter Notebook** — EDA и загрузка данных
- **PostgreSQL** (Postgres.app) — хранилище очищенных данных
- **SQLAlchemy / psycopg2** — связь Python и PostgreSQL
- **Apache Superset** (Docker) — BI-дашборд

## Установка и запуск

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/darialiapun/bank-churn-to-retention.git
cd bank-churn-to-retention
```

### 2. Настройте окружение Python

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3. Поднимите PostgreSQL

Установите [Postgres.app](https://postgresapp.com/) и создайте базу данных `bank_churn_to_retention`.

### 4. Загрузите данные

Откройте `notebooks/01_eda.ipynb` и выполните ячейки — ноутбук очистит данные и загрузит их в таблицу `customers` в PostgreSQL.

### 5. Поднимите Apache Superset

Superset — отдельный open-source проект, его нужно развернуть локально по [официальной инструкции](https://superset.apache.org/docs/quickstart) (через Docker Compose). После запуска подключите в Superset базу `bank_churn_to_retention` через адрес `host.docker.internal:5432`.

### 6. Откройте дашборд

В интерфейсе Superset (`localhost:8088`) создайте датасет на таблице `customers` и соберите графики.
